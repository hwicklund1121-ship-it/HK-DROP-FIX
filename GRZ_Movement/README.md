# GRZ Movement 0.31 — free movement stamina, paid jump and melee


Settings > Game > GUNRUNNERZ FOV now uses the limits shown in the supplied references:

- FOV: **0.5200–1.5599**, step 0.0001.
- View distance: **500–2,000m**.
- Object view distance: **500–2,000m**, capped to view distance.

Values outside the new limits in existing saved preferences are clamped on load. Apply saves the updated values to `$profile:GRZMovementCamera.json`. The existing custom UI and smaller softer text are retained; the broken native-row insertion remains removed. Replace the old PBO rather than loading both.

The range determines the close/wide FOV endpoints. The camera boom, stance pivots, player model, aspect ratio and weapon posture also affect framing, so matching these values alone does not verify an identical camera composition. Gameplay and World camera scripts are unchanged. Test both FOV endpoints, distance endpoints, held zoom and save/rejoin in-game.

Fresh movement-response implementation for DayZ 1.30. Uses 0.06 sprint smoothing, 100 acceleration limit, 0.14 strafe smoothing, a 17-degree turn threshold, 6.5 lean speed and unrestricted water movement speed. Initializes through the native implementation first. No animation assets from LUGU are included or changed.

This baseline matches movement response settings, not every behavior of the legacy movement PBO. Lean inputs remain available when sprint starts. Stamina, weapon sway, weapon lifting, item stance rules, movement-change callbacks, sprint-end cleanup and stance callbacks remain native. The built-in legacy camera policy selects raised stance cameras directly during transitions and restores sprint-camera selection from the movement index. It uses native camera FOV values and your FOV setting; it does not set a fixed FOV angle or force zoom input. Held eye zoom is preserved for standing/crouching movement; exact equivalence to a third-party FOV mod is not established. In particular, it does not abort weapon events or refresh weapon animations during stance changes. These legacy overrides are possible conflict points, not a confirmed diagnosis.

## Install and test

1. Extract the ZIP and load @GRZ_Movement on the client and server where required. Use the same build on both.
2. Disable lwp_movement, ronjam_fix and other movement replacements, including loose legacy 1337/OPM scripts in another PBO. GRZ cannot undo their overrides while they remain loaded.
3. Use the owner's verified working LUGU PBO. Remove previous experimental LUGU replacements and HK shoulder/camera/stance patches. This ZIP deliberately does not ship another LUGU version.
4. First test LUGU alone with required dependencies. Then add GRZ and repeat G → prone → look right → A/D, on flat ground and a hill. Compare rifle, pistol and empty hands. If LUGU alone fails, GRZ cannot establish that the movement mod caused it.
5. Disable StormZz_Zoom and other camera/FOV replacements when testing this build; GRZ now includes its own camera policy. Add other mods one at a time. Check sprint/strafe/lean, crouch, prone, recovery and held middle-mouse zoom. Keep any newly changed RPT/script errors.

Package checks verify PBO checksum, decompression and source round-trip. DayZ script compilation and movement compatibility require in-game validation; they have not been verified here. This is an unsigned test build; signature-enforcing public servers need an appropriate signed release.

Source: GRZ_Movement/scripts/4_World/GRZMovement.c. Rebuild with `python tools/build_grz_movement.py` from the repository root.
